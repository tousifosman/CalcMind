# 2026-08-21

## Connector opacity default flipped: vague at rest, vivid only while selected

### Session log

1. User feedback (screenshot of the live web build): with a linked cell selected, the
   relevant connectors read at a prominent/vivid colour and the rest at a vague, faded
   one — that part worked as designed. But losing focus (deselecting) made *all* the
   connector lines snap back to the vivid colour, including ones that had just been
   faded. The ask: make the vague, faded look the default, and let selection be what lifts
   a link's connectors to full colour, not the other way round.
2. Traced it to `curveOpacity` in `src/canvas/connectors.ts`: it only faded a curve when
   `anyLinkSelected` was true (i.e. the current selection is itself part of some live
   link) — with no link-relevant selection, every curve short-circuited to full opacity
   `1`. That is decision #13's original "all connectors shown" call, but it had drifted
   into "all connectors vivid" — the fan-in/fan-out screenshot in §11.1 only asked for
   curves to stay *drawn*, not to default to full saturation.
3. Fix: dropped the `anyLinkSelected` special case entirely. `curveOpacity` now always
   returns `1` only when the curve's link involves the current selection, and
   `CONNECTOR_UNSELECTED_OPACITY` otherwise — including when nothing is selected at all.
   Recorded as decision #24 in `docs/ARCHITECTURE.md`, superseding the "full opacity
   unless something else is selected" half of decision #13 (the "draw every live link,
   don't hide any of them" half is untouched). Updated `connectors.test.ts`: the
   no-selection case now asserts `CONNECTOR_UNSELECTED_OPACITY` instead of `1`, and added
   an explicit assertion that clearing a selection fades the previously-emphasized curve
   back down rather than leaving it vivid.

### Knowledge revisions

**1. Connector "selection fade" (decision #13) was read as reversible dimming, not a
default state.**
*Previously believed:* connectors should be fully saturated by default, with the fade to
`CONNECTOR_UNSELECTED_OPACITY` reserved for curves the current selection excludes — so the
resting state of the graph is vivid and selection only *removes* colour from what isn't
relevant.
*Now known:* the resting state should be the faded one; a curve only earns full opacity
while it, or its source/reference cell, is the live selection. This is a strict behaviour
change, not a bug fix in the narrow sense — the old code was doing exactly what decision
#13 as originally written asked for; the request was to change that default, so decision
#13 is superseded by #24 rather than corrected.
*What established it:* direct user report against the live build (screenshot), reproduced
in `curveOpacity`'s logic once traced.

Standing lesson: "fade the unselected ones" and "the selected ones light up" describe the
same two-state system but imply opposite resting states — worth pinning down explicitly
which one is the *default* when a decision like #13 is written, not just which curves end
up dim relative to which.
