### Findings

**react-native-web's `TextInput` `onKeyPress` only synthesises printable keys.**
F9 (and other function keys) never reach `NumberNode`'s `onKeyPress`, so a
hardware `+/-` mapped only there is dead while editing. Misleading symptom: `_`
(printable) toggles sign fine from the same handler, which makes F9 look
"broken in the keymap" rather than unreachable. Fix: handle F9 on the same raw
`keydown` listener that already owns Enter/Space for the gesture-handler trap,
and also allow it through AppShell's capture listener when an input is focused.

### Knowledge revisions

**1. "Escape deselects" and "dismiss keypad" are two actions, not one.**
*Previously believed (briefly, mid-implementation):* mapping Escape to both
deselect and hide-keypad in one press was a fine keyboard equivalent for the
mode-strip chevron.
*Now known:* that collapses §8.5's explicit "Escape deselects" into a dismiss,
and hides the keypad the first time the user only meant to clear selection.
First Escape deselects; a second Escape with nothing focused dismisses —
chevron equivalent without rewriting Escape's primary meaning.
*What established it:* §8.5's own Escape bullet, plus the P7.2 criterion that
*every* keypad action (including dismiss) needs a keyboard equivalent.
*Standing lesson:* when one key is already claimed by the architecture doc,
stack a second press (or a modifier) for the new action rather than overloading
the first press.
