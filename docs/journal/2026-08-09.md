## Group-mode keypad: disable (not hide) non-history keys

### Session log

1. User: when a group is selected, disable all keypad keys except undo /
   redo / backspace; if the group has a result, keep operator buttons
   available too. (First pass hid the keys; user clarified disable.)
2. `Keypad` reads `groupSelectedIds` and leaves the full layout visible,
   setting `disabled` on digits, number-editing, and `=`. History stays
   enabled. Operator column (`÷ × − +`) stays enabled only when
   `groupContainsResult` is true; otherwise those ops are disabled too.
3. `dispatchEditorCommand` mirrors that: while a group is active, digits /
   editing / equals / parens no-op; backspace calls new `deleteGroup` (one
   undo entry for the whole set); operator continues from the group's
   result via `continueFromResult`.
4. `selectGroup` prefers a result in the chain as the primary keypad
   target so continuation does not need an extra tap after double-tap /
   Select group.
5. §8.5 / §8.6 updated. Live-checked on PR #144 (hide pass, then disable
   pass).

### Findings

**Select-group fixtures must go through `appendOperatorAndNumber` +
`appendEqualsNode`, not three free `add*Node` calls plus a lone
`appendEqualsNode` on the last number.** Misleading symptom: `selectGroup`
appears to ignore the result (group size 1, operators stay disabled) because
only the equals-append path created a chain, and the tapped operator was
still free.
