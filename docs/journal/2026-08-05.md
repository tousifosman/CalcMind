### Findings

**Repeated continuation stacks every new chain on the same anchor.**
`continueFromResult` always places at `CONTINUATION_OFFSET` from the source
result, so a 1→N fan created only via the keypad lands with coincident endpoints
and looks like one thick curve until the consumer chains are dragged apart.
Misleading symptom: "only one connector appeared after four continuations."
Geometry was fine; positions were identical. Fan verification used a spread
fixture for that reason — not a connector bug.

ships prebuilt ESM with `.web.js` siblings that `resolve.extensions` picks up,
but without babel it is easy to hit the same class of RN-web transform gaps
gesture-handler already required. Add it next to gesture-handler in
`webpack.config.js` when the dependency becomes load-bearing.

## P6b.3 + P6b.4 — Value slider and live scrub cascade

### Session log

1. Picked up P6b.3 (#108) then P6b.4 (#110). Built pure range inference in
   `src/nodes/inferSliderRange.ts` (§8.8: zero → `[0,10]`, positive decade ceiling,
   negative symmetric; Decimal.log to avoid `Math.log10` float traps on exact powers
   of ten and fractions like `0.01`).
2. Built `ValueSlider.tsx` + overlay: popover anchored beneath the selected number
   via `worldToScreen`, editable min/max inputs, pan/tap track (tap → integer snap,
   drag → continuous). Wired into `AppShell`. Same `preventFocusSteal` mousedown
   trade as the keypad so scrubbing does not blur-deselect the TextInput.
3. P6b.4 scrub commands in `store/commands.ts`: `beginValueScrub` /
   `scrubNodeValue` / `endValueScrub`. Whole gesture coalesces into one undo entry
   (not the 500ms keystroke window). Autosave suppress hooked through
   `documentStore.setAutosaveSuppressHandler` → P5.6's `setSuppressed`. Recompute
   coalesced to one flush per animation frame (pending raw always wins).
4. Tests: range inference table, slider popover/bounds, scrub undo coalesce +
   cascade + suppress + rAF coalescing. Mock gained `Gesture.Exclusive`.
5. `tsc` / lint / 609 tests / `build:web` green. Interactive web walk pending in
   this same session.

### Findings

**Range inference needs Decimal, not `Math.log10`.** Exact powers of ten and
sub-1 values (especially `0.01`) drift under `Math.log10` such that `ceil` jumps
a decade. Misleading symptom: `inferSliderRange(0.01)` returning `[0, 0.1]`.
`Decimal.log(10).ceil()` matches the §8.8 formula.

**Slider mousedown must not steal focus from the number TextInput.** Same class
of bug as the keypad (journal 2026-08-04): without `preventDefault` on mousedown,
blur → `deselectNode` → popover unmounts before the scrub lands.

**Scrub undo coalesce is gesture-scoped, not time-scoped.** Reusing
`setNodeRaw`'s 500ms window would split a long scrub into many undo entries.
`beginValueScrub` records `baseStackLength` and merges every subsequent frame
into that one entry for the life of the gesture.

### Knowledge revisions

**1. Scrub frame budget is "one recompute per rAF", not an elapsed-time gate.**
*Previously believed:* throttle by measuring ms since last flush against
`1000/60` and rescheduling while under budget.
*Now known:* coalescing pending raw into a single `requestAnimationFrame` flush
*is* the frame budget — if recompute is slow the JS thread simply does not get
another frame until it is free, and the latest raw still wins. An elapsed-time
gate busy-loops under a sync test scheduler.
*What established it:* first draft infinite-recursed under the test seam that
invokes the scheduled callback synchronously.
