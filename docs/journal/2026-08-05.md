### Findings

**Repeated continuation stacks every new chain on the same anchor.**
`continueFromResult` always places at `CONTINUATION_OFFSET` from the source
result, so a 1→N fan created only via the keypad lands with coincident endpoints
and looks like one thick curve until the consumer chains are dragged apart.
Misleading symptom: "only one connector appeared after four continuations."
Geometry was fine; positions were identical. Fan verification used a spread
fixture for that reason — not a connector bug.

**`react-native-svg` needs an explicit webpack babel `include`.** The package
ships prebuilt ESM with `.web.js` siblings that `resolve.extensions` picks up,
but without babel it is easy to hit the same class of RN-web transform gaps
gesture-handler already required. Add it next to gesture-handler in
`webpack.config.js` when the dependency becomes load-bearing.

## P6b.1 — Labels on the identity

### Session log

1. Picked up P6b.1 (#107). Label storage already lived on the node base (P6.5
   granted identity hue from it); what was missing was lookup-through-identity
   for references, a command, and an edit affordance.
2. Added `identitySourceId` / `labelForNode` in `src/engine/identity.ts`.
   `setNodeLabel` / `editNodeLabel` / `finishEditingLabel` in commands — write
   always lands on the declaring number or result; keystrokes coalesce (§13).
3. `ReferenceNode` renders the source caption via `labelForNode` + `labelHue`
   (caption colour without a declaring-cell ring). Context-menu `Label` opens
   the in-place editor on the identity source.
4. Acceptance test: label a result with three references → all four cells show
   the caption; one undo entry. `tsc` / lint / 598 tests / `build:web` green.
5. Browser walk caught Space truncating multi-word labels (gesture-handler tap
   activation). Fixed in Cell; re-verified "Initial Deposit" sticks on source
   and reference. Ctrl+Z is not wired yet (P7.2) — undo covered by unit tests.

### Findings

**A reference's own `label` field is dead data under §11.1.** Schema still
allows it (node base), and `unlinkFromParent` used to copy `ref.label` onto the
frozen number — but the caption is looked up on the source. After P6b.1,
references ignore their own `label` at render time; unlinking no longer inherits
a source name onto an independent number (correct: that would forge a second
identity caption). Misleading symptom if debugging old fixtures: a reference
JSON with `"label": "…"` will not paint that string.

**Space while editing a label used to commit early on web.** Same class of bug
as NumberNode's hardware-keyboard trap (`docs/journal/2026-08-03.md`):
gesture-handler's web KeyboardEventManager treats a bubbling Space/Enter on a
`GestureDetector` ancestor as tap activation, which blurs the label field mid-
phrase. Symptom: typing "Initial Deposit" left only "Initial". Fix: the same
native `keydown` `stopPropagation` on Cell's label `TextInput` that NumberNode
already uses for raw editing.

### Knowledge revisions

**1. Label editing needs the same Space/Enter trap as number editing on web.**
*Previously believed (implicitly, by shipping the label TextInput without it):*
caption typing is ordinary text input and would not interact with canvas
gestures.
*Now known:* on web, Space mid-label activates the canvas Tap gesture via
gesture-handler's keyboard manager — identical failure mode to NumberNode.
*Cost if ignored:* multi-word labels (the common case — "Initial Deposit",
"Earth mass") silently truncate at the first space.

Open question #5 (when labels land) closed: P6b.1.
