`webpack.config.js` when the dependency becomes load-bearing.

## P6b.1 — Labels on the identity

### Session log

1. Picked up P6b.1 (#107). Label storage already lived on the node base (P6.5
   granted identity hue from it); what was missing was lookup-through-identity
   for references, a command, and an edit affordance.
2. Added `identitySourceId` / `labelForNode` in `src/engine/identity.ts`.
   `setNodeLabel` / `editNodeLabel` / `finishEditingLabel` in commands — write
   always lands on the declaring number or result; keystrokes coalesce (§13).
3. `ReferenceNode` renders the source caption via `labelForNode` + `labelHue`
   (caption colour without a declaring-cell ring). Context-menu `Label` opens
   the in-place editor on the identity source.
4. Acceptance test: label a result with three references → all four cells show
   the caption; one undo entry. `tsc` / lint / 598 tests / `build:web` green.
5. Browser walk caught Space truncating multi-word labels (gesture-handler tap
   activation). Fixed in Cell; re-verified "Initial Deposit" sticks on source
   and reference. Ctrl+Z is not wired yet (P7.2) — undo covered by unit tests.

### Findings

**A reference's own `label` field is dead data under §11.1.** Schema still
allows it (node base), and `unlinkFromParent` used to copy `ref.label` onto the
frozen number — but the caption is looked up on the source. After P6b.1,
references ignore their own `label` at render time; unlinking no longer inherits
a source name onto an independent number (correct: that would forge a second
identity caption). Misleading symptom if debugging old fixtures: a reference
JSON with `"label": "…"` will not paint that string.

**Space while editing a label used to commit early on web.** Same class of bug
as NumberNode's hardware-keyboard trap (`docs/journal/2026-08-03.md`):
gesture-handler's web KeyboardEventManager treats a bubbling Space/Enter on a
`GestureDetector` ancestor as tap activation, which blurs the label field mid-
phrase. Symptom: typing "Initial Deposit" left only "Initial". Fix: the same
native `keydown` `stopPropagation` on Cell's label `TextInput` that NumberNode
already uses for raw editing.

### Knowledge revisions

**1. Label editing needs the same Space/Enter trap as number editing on web.**
*Previously believed (implicitly, by shipping the label TextInput without it):*
caption typing is ordinary text input and would not interact with canvas
gestures.
*Now known:* on web, Space mid-label activates the canvas Tap gesture via
gesture-handler's keyboard manager — identical failure mode to NumberNode.
*Cost if ignored:* multi-word labels (the common case — "Initial Deposit",
"Earth mass") silently truncate at the first space.

Open question #5 (when labels land) closed: P6b.1.

## P6b.2 — Declare-and-label idiom

### Session log

1. Picked up P6b.2 (#109) on a branch off P6b.1. The idiom's pieces already
   existed (typing, `=`, label, continuation); what blocked "as a user would
   type it" was selection after `=` landing on the equals node, so the next
   operator could not continue without a manual tap on the result.
2. Added `appendEqualsForSelection` — returns the result when evaluation
   succeeds, else the equals. Keymap `=` uses it. Integration test
   `declareAndLabel.integration.test.ts` walks `10000` → `=` → label →
   `+ 2 =` with en-US locale assertions.
3. `tsc` / lint / tests / `build:web` green.

### Findings

**After `=`, select the result, not the equals.** P4.9's own keymap tests had
to `selectNode(result)` by hand before every continuation — evidence the
dispatcher never put selection where §8.7 needs it. Misleading symptom: typing
`10 = +` appears to no-op (result branch never runs; equals is selected).
P6b.2's declare-and-label walk made that gap load-bearing.

### Knowledge revisions

**1. Completing a chain should select the answer.**
*Previously believed (implicitly, by `selectNode(appendEqualsNode(...))`):*
selecting the equals glyph after `=` is fine; the user will tap the result.
*Now known:* the declare-and-label idiom and §8.7 continuation both act on the
result next; leaving equals selected forces an extra tap that no acceptance
test covered until P6b.2. `appendEqualsForSelection` is the fix.

## P6b.3 + P6b.4 — Value slider and live scrub cascade

### Session log

1. Picked up P6b.3 (#108) then P6b.4 (#110). Built pure range inference in
   `src/nodes/inferSliderRange.ts` (§8.8: zero → `[0,10]`, positive decade ceiling,
   negative symmetric; Decimal.log to avoid `Math.log10` float traps on exact powers
   of ten and fractions like `0.01`).
2. Built `ValueSlider.tsx` + overlay: popover anchored beneath the selected number
   via `worldToScreen`, editable min/max inputs, pan/tap track (tap → integer snap,
   drag → continuous). Wired into `AppShell`. Same `preventFocusSteal` mousedown
   trade as the keypad so scrubbing does not blur-deselect the TextInput.
3. P6b.4 scrub commands in `store/commands.ts`: `beginValueScrub` /
   `scrubNodeValue` / `endValueScrub`. Whole gesture coalesces into one undo entry
   (not the 500ms keystroke window). Autosave suppress hooked through
   `documentStore.setAutosaveSuppressHandler` → P5.6's `setSuppressed`. Recompute
   coalesced to one flush per animation frame (pending raw always wins).
4. Tests: range inference table, slider popover/bounds, scrub undo coalesce +
   cascade + suppress + rAF coalescing. Mock gained `Gesture.Exclusive`.
5. `tsc` / lint / 609 tests / `build:web` green. Interactive web walk: slider
   raises on select, scrub cascades through a two-level continuation chain,
   duplicate endpoint labels (input + Text) caught live and fixed so the
   editable inputs *are* the labels.
6. Follow-up confirm: labels once each; cascade still live after the fix.

### Findings

**Range inference needs Decimal, not `Math.log10`.** Exact powers of ten and
sub-1 values (especially `0.01`) drift under `Math.log10` such that `ceil` jumps
a decade. Misleading symptom: `inferSliderRange(0.01)` returning `[0, 0.1]`.
`Decimal.log(10).ceil()` matches the §8.8 formula.

**Slider mousedown must not steal focus from the number TextInput.** Same class
of bug as the keypad (journal 2026-08-04): without `preventDefault` on mousedown,
blur → `deselectNode` → popover unmounts before the scrub lands.

**Scrub undo coalesce is gesture-scoped, not time-scoped.** Reusing
`setNodeRaw`'s 500ms window would split a long scrub into many undo entries.
`beginValueScrub` records `baseStackLength` and merges every subsequent frame
into that one entry for the life of the gesture.

### Knowledge revisions

**1. Scrub frame budget is "one recompute per rAF", not an elapsed-time gate.**
*Previously believed:* throttle by measuring ms since last flush against
`1000/60` and rescheduling while under budget.
*Now known:* coalescing pending raw into a single `requestAnimationFrame` flush
*is* the frame budget — if recompute is slow the JS thread simply does not get
another frame until it is free, and the latest raw still wins. An elapsed-time
gate busy-loops under a sync test scheduler.
*What established it:* first draft infinite-recursed under the test seam that
invokes the scheduled callback synchronously.
