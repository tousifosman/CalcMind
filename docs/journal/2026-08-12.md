# 2026-08-12

## `Create link` keypad button, decimal/sign relocated into the digit grid

### Session log

1. User asked for a keypad layout change: move `.` to sit under-left of `0` (i.e. under `1`),
   move `+/-` to sit under-right of `0` (under `3`), and put a new `Create link` button — icon,
   blue fill — in the number-editing row slot `.` used to occupy. Enabled only when a number or
   result is selected; disabled otherwise.
2. Relocated decimal and `+/-` from the dedicated `editingRow` into the digit grid's `0` row
   (`Keypad.tsx`), replacing the two spacer views that used to centre `0` there. Added a
   `gridEditingKey` style override (`height: 48`) so they match the digit row's cell height
   instead of the generic 44px `key` height — otherwise the row would have a visible step.
   Removed the now-dead `digitSpacer` style.
3. Added the `Create link` button in decimal's old `editingRow` slot: `Key` gained an optional
   `style` prop (needed for both this and the height override above) so per-instance overrides
   don't need a bespoke component the way `OperatorKey`/`EqualsKey` have one each.
   `react-native-heroicons/outline/LinkIcon`, filled `identityHues[0]` (`#2F6BFF`) — reused
   rather than inventing a new blue, since that hue is already the palette's primary blue and
   already checked for deuteranopia/protanopia (`paletteAccessibility.ts`).
4. Wired a new `{ region: 'createLink' }` `KeypadKey` / `EditorCommand` variant through
   `keymap.ts`. Deliberately narrower than the `Create link` context-menu action
   (`createLinkToValue` itself is unchanged and still accepts a live reference too, per
   yesterday's work) — the keypad button only enables for `selectedKind === 'number' | 'result'`,
   matching exactly what the user specified. No hardware-keyboard shortcut was requested or added.
5. Verified live: built and served the web target, drove it with the same headless-Chromium
   session from yesterday. Screenshots confirm the new bottom row reads `. 0 +/-` under the
   `7/4/1`, `0`, and `9/6/3` columns respectively; that the Link button is greyed out with
   nothing selected and vividly blue once a number is selected; and that pressing it creates a
   connected reference cell — coincidentally also painted `identityHues[0]` since it was the
   first identity assigned in that document, which nicely echoes the button's own colour.
6. Updated `ARCHITECTURE.md` §8.5's keypad table and bullets to describe the new layout and the
   `Create link` key's eligibility rule. Updated `Keypad.test.tsx`: the digit-grid/editing-row
   split changed structurally (the `['.', '+/-', '()']` text-label assertion for
   `keypad-number-editing` no longer holds — that row now renders `['()']`, since `Create link`
   is icon-only), and added a dedicated `describe('Create link keypad button (§8.6)')` block
   covering presence, the a11y name, disabled-by-default, enabled for a selected number/result,
   disabled for a reference/operator/group-selection/Select-all, and that pressing it reports
   `{ region: 'createLink' }`.
